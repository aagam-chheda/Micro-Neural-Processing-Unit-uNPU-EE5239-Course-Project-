# Task 009 — CSR / register map

## Goal

Build `unpu_csr`, the 8-register file the CPU will eventually configure a
matmul through. This is the register *storage and semantics* only — word
select in, word data in/out, plus the special behaviors (write-1-to-pulse
START, read-only STATUS). It does not know about any bus protocol; the
native slave FSM that decodes real bus transactions into this module's
simple select/write/read port is a separate task (step 13) — deliberately
split, same reasoning the notebook gives for splitting FSMs generally
(`docs/unpu-notebook.html` §07: "Three small machines... are individually
provable. One machine with forty states is not.").

## Register map (confirmed 8-register list; offset layout still Planning's proposal)

`docs/session-handoff.md` §6/§12: the 8-register list itself (`src_A`,
`src_B`, `dest_C`, `dim_M`, `dim_N`, `dim_K`, `npu_ctrl`, `npu_status`) is
**PM-directed**. The specific offset assignment below is
`docs/planning/unpu-architecture.html` §3's proposed layout, **not yet
PM-confirmed** — build against it, don't block on that confirmation (same
status quo the plan has already been operating under since task 006).

| Offset | Word sel | Name | Access | Contents |
|---|---|---|---|---|
| 0x00 | 0 | `src_A` | R/W | Pointer to `A` [M×K], signed int8, in SRAM |
| 0x04 | 1 | `src_B` | R/W | Pointer to `B` [K×N], signed int8, in SRAM |
| 0x08 | 2 | `dest_C` | R/W | Pointer to `C` [M×N], int32, in SRAM |
| 0x0C | 3 | `dim_M` | R/W | Rows of A/C, bits[2:0] only |
| 0x10 | 4 | `dim_N` | R/W | Columns of B/C, bits[2:0] only |
| 0x14 | 5 | `dim_K` | R/W | Inner dimension, bits[2:0] only |
| 0x18 | 6 | `npu_ctrl` | R/W | bit0 START (W1P, reads 0) · bit1 SIGNED · bits[31:2] reserved |
| 0x1C | 7 | `npu_status` | RO | bit0 DONE · bit1 ERROR · bits[4:2] error_code · bits[31:5] reserved |

`npu_status` bits 1 and [4:2] (ERROR / error_code) are **Planning's own
addition**, not in the architecture doc's bit0-only sketch — this is
exactly the hookup task 006 built `unpu_seq.error`/`error_code` for
("exist so a later task can wire them into npu_status," `plan.md` step 8
note). Placed in previously-unspecified bits of an already-not-PM-
confirmed register, same footing as everything else marked provisional
here.

`dim_M`/`dim_N`/`dim_K` legality (1–4) is **not** validated by this
module — `unpu_seq`'s `LATCH_CFG` state already does that (task 006).
Don't duplicate it here; `unpu_csr` stores whatever is written, verbatim.

The notebook's old open question ("what does `NPU_CTRL[1]` RESET clear?",
§05 B1) is moot — that was the 5-register APB-era layout. The confirmed
8-register `npu_ctrl` has no RESET bit; bit1 is SIGNED. Don't resolve
that old question, it doesn't apply to this register map.

## Interface

```systemverilog
module unpu_csr (
  input  logic         clk,
  input  logic         rst_n,          // async, active-low

  // Register-level R/W port -- bus-protocol-agnostic. sel is a WORD
  // offset within the full 4 KB register window (0x4000_0000-
  // 0x4000_0FFF is 1024 words) -- covers both the 8 real registers and
  // the reserved range above them, so this module can itself implement
  // "unmapped reads as zero, writes ignored" (docs/unpu-notebook.html
  // §05 B1, still-good decision despite that section otherwise being
  // stale APB material) rather than leaving it for step 13 to bolt on.
  input  logic [9:0]   csr_sel,
  input  logic [31:0]  csr_wdata,
  input  logic         csr_wen,        // 1-cycle pulse: commit csr_wdata to csr_sel's register this cycle
  output logic [31:0]  csr_rdata,      // combinational read of csr_sel, no read-enable needed (reads never stall)

  // Consumer-facing outputs -- latched register contents, for unpu_seq /
  // unpu_dma to read directly once step 14 wires this in
  output logic [31:0]  src_a,
  output logic [31:0]  src_b,
  output logic [31:0]  dest_c,
  output logic [2:0]   dim_m,
  output logic [2:0]   dim_n,
  output logic [2:0]   dim_k,
  output logic         mode_unsigned,  // = ~npu_ctrl[1] -- SIGNED=1 means mode_unsigned=0, see polarity note below
  output logic         start_pulse,    // 1-cycle pulse, registered one cycle after a qualifying START write -> unpu_seq.start

  // Status inputs -- from unpu_seq
  input  logic         done_i,         // 1-cycle pulse from unpu_seq.done; latches npu_status.DONE
  input  logic         error_i,        // level, already latched upstream by unpu_seq (task 006) -- pass through, don't re-latch
  input  logic [2:0]   error_code_i    // from unpu_seq.error_code, pass through alongside error_i
);
```

### Polarity note (Planning's call, flag back if it's wrong)

The architecture doc labels `npu_ctrl` bit1 "SIGNED mode" without stating
polarity. Reading it literally — bit1=1 means "operating in signed
mode" — makes it the *inverse* of `unpu_pe`'s `mode_unsigned` convention
(0=signed, 1=unsigned). So `mode_unsigned = ~npu_ctrl_reg[1]`. Get this
backwards and every matmul silently runs the wrong sign interpretation
without any test in isolation catching it (only an end-to-end check
against a case where signed/unsigned actually diverge would) — the
acceptance criteria below require checking this explicitly, not just
that the bit round-trips.

### START / DONE interaction

- `start_pulse` is a registered pulse: `start_pulse <= csr_wen &&
  (csr_sel==6) && csr_wdata[0]`. One cycle after the qualifying write,
  not the same cycle — clean synchronous handoff, matches the Moore-
  output discipline used everywhere else in this design (notebook §07.1,
  task 006's `unpu_seq`).
- `npu_ctrl`'s bit0 always reads back 0, regardless of what was written —
  it is never stored as 1.
- `npu_status.DONE`: `if (start_pulse) status_done <= 0; else if (done_i)
  status_done <= 1;` — a new START always clears the previous run's DONE
  before any new one can set it (start-clear takes priority; in real
  operation these can't coincide anyway since `done_i` only fires a full
  compute pass after `start_pulse`, but define the priority for
  determinism).
- `npu_status.ERROR`/`error_code` are pure combinational passthroughs of
  `error_i`/`error_code_i` — `unpu_seq` already latches `error` itself
  (task 006: "latched; cleared only by the next start"), so `unpu_csr`
  doesn't need its own latch here.
- Writes to `npu_status` (`csr_sel==7`) are accepted (`csr_wen` asserted)
  but have **no effect** — "NPU_STATUS writes are silently discarded"
  (notebook §05 B1, still-good decision: "It is R/O in the spec; a
  generic register array would let the CPU clobber its own DONE bit.").
- Reserved bits (`npu_ctrl[31:2]` beyond bit1, `npu_status` beyond the
  bits above, `dim_*`'s bits[31:3]) are write-ignored and read as 0.
- `csr_sel` values 8–1023 (unmapped): `csr_rdata` reads 0, `csr_wen`
  writes are accepted but have no effect on any real register.

## Testbench (`tb/unpu_csr_tb.sv`)

Instantiate `unpu_csr` alone — no datapath modules needed, this is a
pure control-plane module. Drive `done_i`/`error_i`/`error_code_i`
directly as testbench stimulus (standing in for `unpu_seq`, same role the
testbench has played for every not-yet-integrated module so far).

### Directed

- All 8 real offsets: write then read back `src_A`/`src_B`/`dest_C` (full
  32-bit) and `dim_M`/`dim_N`/`dim_K` (confirm storage is unvalidated —
  write 0 and write 7, both a legality-check would reject, and confirm
  both simply round-trip verbatim, since that check is deliberately
  `unpu_seq`'s job, not this module's).
- `npu_ctrl` bit0: write `32'h1`, confirm `start_pulse` asserts for
  exactly one cycle the cycle after, and confirm `npu_ctrl` reads back
  with bit0 = 0 immediately and on every subsequent read.
- `npu_ctrl` bit1: write `32'h2`, confirm readback bit1=1 **and**
  `mode_unsigned` output reads 0 (the polarity check — don't skip this,
  see the note above). Write `32'h0`, confirm `mode_unsigned` reads 1.
- Write `32'h3` (both bits together): confirm `start_pulse` still fires
  and bit1 still latches independently — they don't interfere.
- `npu_status.DONE`: pulse `done_i`, confirm `npu_status` bit0 reads 1
  afterward and **stays 1** across several idle cycles (sticky, not a
  pulse-through). Then issue a real START write (`csr_sel=6,
  wdata[0]=1`), confirm bit0 clears the cycle `start_pulse` asserts.
- `npu_status.ERROR`: drive `error_i=1`, `error_code_i=3'd1`, confirm
  `npu_status` bits [4:2]=`3'd1` and bit1=1; drop `error_i`, confirm both
  clear (pure passthrough, no CSR-side latch).
- `npu_status` write attempt: write some nonzero pattern to `csr_sel==7`,
  confirm a subsequent read is unaffected by the write (still reflects
  `done_i`/`error_i` state, not the written value).
- Reserved-range: write and read at `csr_sel` = 8, 255, 1023 — reads
  return 0, and a follow-up read of every one of the 8 real registers
  confirms none of them changed as a side effect.

### Plus CRV

Randomized read/write sequences across the full `csr_sel[9:0]` range
(0–1023, so both real and reserved offsets get hit), including
back-to-back writes with no idle cycle between them. Self-check against
a **shadow model** you maintain in the testbench (plain SV variables
mirroring expected register contents, applying the exact same semantics
as above: START self-clears, `npu_status` is RO+passthrough with DONE
sticky-until-next-start, reserved offsets read 0) — there's no golden-C
oracle for this module, register semantics are the reference. At least
64 iterations, seeded (e.g. `32'h5eed0009`, or your own draw — print
whichever), reproducible.
