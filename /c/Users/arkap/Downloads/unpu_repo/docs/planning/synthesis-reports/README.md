# uNPU synthesis reports (Design Compiler, SCL 180 nm, ss corner)

Raw reports of the synthesis runs of the 4x4 INT8 systolic macro `unpu_top`, copied here from the (git-ignored) `syn/out/` so they can be
read from the repository. Nothing in these files was edited. The netlist is not included (1.2 MB; it is regenerated by `syn/dc_run.tcl` /
`constraints/pm_dc_script_unpu.tcl`).

## Which run to read

| Folder | Date | Status |
|---|---|---|
| `round3-2026-10-14/` | 2026-10-14 | **CURRENT.** The run whose netlist went into place and route (clean-name copy `unpu_top_cn.dc.v`) and was checked by gate-level simulation |
| `round1-2026-10-08/` | 2026-10-08 | First run, superseded (a 1.0 ns transition limit that cannot be met forced extra buffering) |

## Headline numbers, round 3

| Item | Value |
|---|---|
| Tool, library | dc_shell T-2022.03-SP5, `tsl18fs120_scl_ss` (ss: 1.62 V, 125 C), wire load model 140000 |
| Clock | 20 ns (50 MHz), ideal; setup uncertainty 1.5 ns |
| Worst setup path | `paddr[3]` to `prdata[14]` (combinational APB read path): arrival 11.49 ns, required 11.50 ns, **slack +0.01 ns (MET)** |
| Why +0.01 | the path has 7.0 ns input and 7.0 ns output external delay (35% + 35% of the period) and 1.5 ns uncertainty: 4.5 ns budget; DC stops optimising once the slack is just positive, so +0.01 is not extra margin |
| Cells | 12,614 cells: 10,022 combinational, 2,465 sequential (flops), 0 macros; 7,452 ports (summed over modules) |
| Cell area | 429,161.24 um2 (combinational 251,012.34; buf/inv 19,857.17; flops 178,148.90) |
| Total area | 442,295.85 um2 (adds 13,134.61 um2 of estimated net interconnect) |
| Power (low effort, no switching annotation) | cell internal 6.0775 mW (95%), net switching 327.25 uW (5%), about 6.40 mW dynamic; leakage 5.57 uW |

`violators.rpt` lists one violation, `max_area`: required 0 against 442,295.84 um2. That is expected and not a failure: the PM's script
sets `set_max_area 0`, which means "minimise", and DC reports it as violated by definition.

## What these reports do NOT cover

- ss corner only: no hold analysis here (hold uses the ff library in the layout flow, ICC2/PrimeTime).
- Ideal clock, wire-load-model estimates, no wire delay from layout. After place and route the timing is re-measured.
- The interface budgets (7 ns in/out, driving cell, 1 pF load, transition limits) are labelled assumptions in `constraints/unpu_top.sdc`;
  only the 20 ns period and the 1 pF output load are facts.
- Power is a low-effort estimate without switching activity: not meaningful as a power figure.
- No scan chain (DFT omitted, confirmed by the PM).
