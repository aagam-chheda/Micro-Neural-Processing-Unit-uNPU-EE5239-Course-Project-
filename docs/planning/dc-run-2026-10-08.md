# DC run summary: PM script, ss corner, harsh constraints (2026-10-08)

Quick reference for the first Design Compiler run of `constraints/pm_dc_script_unpu.tcl`
(reads `constraints/pm_unpu_top.sdc`). The user ran it by hand on the server, in their
own clone, ss corner only. Raw reports live on the server in `syn/out/pm_flow/` and, as a
local copy, in `syn/out/pm_flow_server/` (git-ignored, not committed). Context and open
items: `docs/session-handoff.md` section 18.6 and `docs/planning/plan.md`.

Repo state when the run was made: constraints at `b264b69`, RTL frozen since `9f5deab`.
Tool: dc_shell T-2022.03-SP5. Library: `tsl18fs120_scl_ss`, 1.62 V, 125 C, wire load `140000`.

Where the 4.48 ns goes:

| Stage | Delay |
|---|---|

smallest inverter), so +0.02 ns is NOT margin.

## Constraints as written back by DC

| Item | Applied |
|---|---|
| Clock | 20 ns; uncertainty setup 1.5 / hold 0.5; transition 0.6 |
| Input delays | 7 ns on 67 APB inputs; 8 ns on 34 DMA and `rst_n` inputs; min 0 |
| Output delays | 7 ns on 33 APB outputs; 8 ns on 69 DMA outputs; min -0.5 |
| Boundary | `buffd1` drivers; 0.2 pF on 101 inputs; 1 pF on 102 outputs |
| Limits | max transition 1 ns; max capacitance 2 pF |

Every number except the 20 ns period and the 1 pF output load is a deliberately harsh
assumption (see the header of `constraints/pm_unpu_top.sdc`). None may be changed to
close timing without a written reason and the user's approval.

## Netlist notes

- No don't-use cells (`slnht*`, `skbrb*`, `slbhb*`, `slnhn*`, `slnln*`, `mx08d*`): 0 hits.
  The script does not exclude them; DC just did not pick them.
- 16 `assign` statements and escaped names remain because `change_names` is not run
  (known script defect; matters for ICC2 and gate-level simulation).
- One high-fanout net warning (TIM-134), most likely the buffered reset `n118`, which
  feeds all eight sub-blocks (about 2,465 flops). Not yet confirmed from DC. The reset is
  asynchronous active-low in all 28 `always_ff` blocks.
- `set_input_delay 0` from the PM script also lands on the `clk` port. Harmless in DC.

## Not covered by this run

Register-to-register paths, hold, the ff corner, `check_design`, `check_timing`, any
ICC2 or PrimeTime read of the SDC, gate-level simulation of the netlist.
