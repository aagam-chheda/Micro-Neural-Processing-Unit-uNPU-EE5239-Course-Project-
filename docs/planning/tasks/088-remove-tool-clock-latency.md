## Decision and evidence (user: "yes go with your recommendation", 2026-11-10)

ICC2 writes `set_clock_latency <v> [get_clocks {clk}]` into the block (run 1 exported SDCs: 0.806866 ss, 0.379753 ff; no script of ours sets it). ICC2 then counts it as the I/O reference latency; PrimeTime ignores it (propagated clock, 0.00 at the pin). 086 experiment A0 (`remove_clock_latency [get_clocks -filter "is_virtual == false"]` per scenario, then a re-report) gave PrimeTime's numbers on the four example paths: hold slack -0.3494 (PT -0.35), output required 10.5000 (PT 10.50), source-flop launch 0.9188 (PT 0.92); reg-to-reg unchanged; in2out setup 0.0212 -> 0.0081. The decision: remove the line inside the flow so that ICC2 optimises in PrimeTime's convention. No margin, no SDC text from the PM, no uncertainty change. It is not a tuned constraint: it deletes a tool artefact the instructor never gave. Say so in the script comments.
