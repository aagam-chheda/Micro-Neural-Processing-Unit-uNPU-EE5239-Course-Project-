## Contents (propose the exact tree; keep it small and navigable)

1. `README.md` (the integration datasheet, 3 to 5 pages): what the macro is (4x4 INT8 weight-stationary systolic matmul, 32-bit accumulator, 50 MHz, single-stage PE, SCL 180 nm), the port list with directions/widths and the groups (APB 32-bit register interface: `paddr`, `pwdata`, `pwrite`, `psel`, `penable`, `prdata`, `pready`; DMA master `dma_addr[31:0]`, `dma_wdata[31:0]`, `dma_rdata[31:0]`, `dma_wstrb[3:0]`, `dma_valid`, `dma_ready`; `clk`, `rst_n` synchronous active-low), the address window 0x4000_0000 to 0x4000_0FFF and the 8-register native-interface map (take it from the RTL `unpu_csr.sv`/documents; mark what the PM has NOT confirmed), the timing contract (cycle numbers) in one table, the behaviour of the combinational APB read path (`paddr` -> `prdata`, no flop, 35 percent budgets), reset behaviour, interrupt/status if any, the DMA protocol; the physical facts: die 885.6 x 885.6 um, 206 pins (204 signal + VDD, VSS), pin plan (right edge: APB + `clk` + `rst_n` on M3; top edge: DMA on M2; power pins on the BOTTOM edge: 14 TOP_M pins at 56 um pitch, alternating VSS/VDD from x = 60.48), no signal pins on the left edge or bottom, halo 10 um, orientation R0, OBS on all four metals (no routing over the macro), the clock: internal CTS, insertion delay and skew (ff latency 0.56 ns / skew 0.32 ns; ss 1.26 / 0.75: from the clock QoR report; the PM question Q14 about the latency limit is still open), supply 1.62 V (check the corner), the power estimate (8.43 mW at default activity: say it is not meaningful); the assumed interface timing (input delays 35/40 percent, output 35/40 percent of 20 ns, input min 0, output min -0.5, driver `buffd1`, input wire load 0.2 pF, output load 1.0 pF) and what the top level must provide or check on its side.
2. `layout/`: the GDS (local only, see above), the LEF (`unpu_top.lef`: 885.6 x 885.6, 206 pins), the DEF, `pin_list.csv` (pin, direction, layer, side, x/y offset in um) generated from the final LEF by a script you write and test (say how many of the 204 signal pins sit on which edge/layer and compare with the plan above: report a difference as a finding), a PNG/PDF of the pin map is optional.
3. `netlist/`: `unpu_top_pnr_sim.v` (no PG pins: for integration simulation) and `unpu_top_pnr_pg.v` (PG pins: for LVS at top level), and a note that the delivered netlist is NOT the synthesis netlist (the flow added buffers and resized cells: list the categories and counts: 54 early port buffers, 1 antenna buffer, 11 hold buffers, 10 resizes) — this closes the open item "tell the PM the macro netlist changed"; the zero-delay RTL-vs-netlist evidence (GLS of the synthesis netlist 343,341 checks and post-layout A to D).
4. `timing/`: the exported SDCs (ss, ff), the SDF files (3.0), the SPEF files (gz if large), and `interface_timing.md`/`.csv`: for every port group the arrival/required/slack from PrimeTime (setup ss and hold ff, SI off and on) taken from the final reports (use the path reports of the worst path per group), the clock-to-output and input-to-clock figures the top level needs, with the reference clock convention stated (PrimeTime launches/captures I/O at the clk pin with zero latency: the macro's insertion delay counts against the budgets). NO macro `.lib` exists: the PM question "how the macro .lib is produced and by whom" is still open in the handoff and `write_lib` is not available here (PT-063 'Library Compiler executable path is not set'): say so in the README as a known gap, do not invent a `.lib`.
5. `signoff/`: copies of the final Calibre reports (DRC, antenna, LVS: `.rpt` + the summary lines), the PrimeTime summaries (6 runs), design-rule report, the post-layout verdicts (A to D) with the stated limitations, utilization, congestion, the sdc_compare result, the clock QoR.
6. `verification/` (optional, small): the testbench and the golden model source so the top-level team can reproduce the function test, the test vectors generator, how to run (from `Final/scripts`).
7. `open_items.md`: what the top level or the PM still has to decide or confirm (Q14 latency/skew limit; whether the macro deliverable includes Calibre dummy fill: the chip-finishing document says dummy fill is done by Calibre at chip level, our GDS contains ICC2 metal fill; the `.lib` question; pin order confirmation; supply names `VDD`/`VSS`; PM confirmation of the register map; interrupt line if any) and the known limitations of our sign-off (SDF classes, SI margins, congestion 1.97 percent, ICC2's remaining clock-path transition nets (the 0.40 ns CTS target was not carried into the SDC), the 18 PG missing-via items, no decaps in the PDK).
8. `INDEX.md`: every file with size, sha256, source path in the run, the commit, and the date. `tools/verify_deliverables.sh` (bash): checks the index, that no file over 50 MB is in git, that no `*.gds*` is staged, that the key numbers in the README equal those in the signoff files, and that the pin list matches the LEF (206 pins, 204 signal).
